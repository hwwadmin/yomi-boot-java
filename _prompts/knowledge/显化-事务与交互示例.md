### 3.5 单上下文用例内交互流程

> **单上下文**指同一限界上下文内一次 **UseCase 用例** 的执行链，不是跨模块「编排」。
> 默认链路：**Controller → UseCase → DomainService → DomainServiceImpl → DomainRepository → DomainRepositoryImpl → DB**。

**执行规则**：

- 每个 **UseCase 用例** 一个交互组；**用例入口**写 `*UseCase#execute`，不写 HTTP 路径
- 跨上下文能力在 §3.6，本章只写本域 UseCase→DomainService 链
- 步骤须经过 **Request → Model →（领域规则）→ Entity**，禁止 UseCase 直写 SQL
- 需标明每一步的数据形态（Request/Response、基础类型、Model、Entity）
- 需标明校验点：Request 入参校验（UseCase）、领域不变量（DomainService）
- **写操作交互组强制步骤**（缺任一项视为未完成显化）：
  0. 组首标明 Step 1 决策结论：是否写数据、是否开本地 DB 事务、传播关系（§3，与 §3.4.2 Step 1 表一致）
  1. 若决策为开事务：标明 `@Idempotent` + `@Transactional` **进入点**与幂等键
  2. 事务闭包内步骤须使用 当前 `@Transactional` 方法（不得写「继续用外层 ctx 写库」）
  3. 持久化步骤写明 **DomainRepositoryImpl** 经 `MyBatisDao`/`Mapper` 在同一事务内写库
  4. 标明闭包变量捕获方式；默认 `@Transactional` 在 `execute` 时，Request→Model→Response 同属该闭包；**外部 HTTP/Redis 不得**出现在闭包内步骤
  5. 若定义补偿方法，说明补偿步骤与快照字段来源（调用方 payload）
  6. 若决策为不开事务但仍写数据：组内须复述强理由，并说明失败时的一致性后果

#### 跨域交互组 1：查询主体 Profile（含角色）（**示例域**）

**参与领域**：主体领域 → 角色领域

**用例入口**：`GetProfileUseCase#execute`（编排多个 DomainService）

| 4 | `RoleDomainServiceImpl` | 本域 Repository 链 | `List<RoleModel>` | 仅有效角色 |
| 5 | `GetProfileUseCase#execute` | Model → `GetProfileResponse` | `GetProfileResponse` | 字段齐全 |

#### 跨域交互组 2：编排删除角色（跨模块写示例）

**参与领域**：调用方 → 角色领域（+ 可选 token 副作用）

**用例入口**：`OrchestrateRoleDeleteUseCase#execute`（编排角色域 DomainService）

| 步骤 | 执行方 | 操作描述 | 传递数据（类型） | 约束 |
| ---- | ------ | -------- | ---------------- | ---- |
| 1 | `OrchestrateRoleDeleteUseCase#execute` | 前置校验；组装幂等键与补偿快照 | 编排请求体 | 编排方不写本库 |
| 2 | `RoleDomainService#delete` | 编排 UseCase 直调；领域内事务闭包 | `DeleteRoleCommand`（Model） | 按需：`@Transactional` 在 `RoleDomainServiceImpl#delete`（spec 第十章） |
| 3 | `RoleDomainService#deleteCompensate` | 按快照恢复 | 含 `Previous*` 字段 | 快照由编排方传入 |
| 4 | `OrchestrateRoleDeleteUseCase#execute` | token 撤销等非 DB 副作用 | subjectId 列表 | 不进角色 DB 闭包 |

**跨域写用例骨架**（`OrchestrateRoleDeleteUseCase`）：`execute` 内按序调用 `RoleDomainService#delete` / `#deleteCompensate`；token 等副作用在 DB 闭包外；补偿条件见 spec 第十一章、第十三章。
