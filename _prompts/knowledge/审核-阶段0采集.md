# 显化审核 · 阶段 0（能力画像与按需采集）

> 画像命中时 Read 本文；硬门禁与 AskQuestion 要求以本文为准。主流程见 `skills/显化审核.md` §3.1。

## 阶段 0：能力画像与按需采集门禁

**目标**：在进入任何实质审核前，按 spec 能力画像**按需**采集规模与并发假设；**禁止无脑全量问卷**，**禁止猜测**未确认的峰值/强度/表量等事实。

**并发两轴（对象不同，分清单、分采集、分打星）**：

| 轴 | 名称 | 对象（唯一） |
| -- | ---- | ------------ |
| 一 | **接口并发** | **仅 HTTP 接口**（路由/Controller 契约） |
| 二 | **非接口并发** | **明显需要并发考量**的**方法**，或**整段流程/能力设计**（非 HTTP） |

Kafka Consumer / cron / 库导出方法等 **不进第一轴**；属第二轴（方法或流程）。禁止第三轴。第二轴 **宁缺毋滥**，不是凡方法、凡流程都问。

**硬门禁**：适用采集项未获用户确认前，禁止进入阶段 1，禁止输出 audit 终稿，禁止打吞吐星级。若画像后**无任何适用采集项**（例如无表、无 HTTP、无第二轴候选），须在 audit §0 记录画像与「全部跳过」原因后，**可直接进入阶段 1**。

#### 步骤 A：能力画像（只扫 spec，不臆造）

| 画像信号 | 判定依据（示例） |
| -------- | ---------------- |
| 有表/持久化 | 含 DDL、表变更、Repo 持久化读写、明确落库 |
| 有 HTTP 读/写 | Controller/路由清单中存在读或写 HTTP 接口 |
| 有非接口并发候选 | 见步骤 C2「明显需要」信号（库导出热路径、消费/定时处理函数或整段并发流程等） |
| 可能涉及允许策略 | **仅当** spec **已写明**深分页 / 缓存 / 异步削峰 / 限流（含明确选用或排除）。禁止因「审核或许会建议」而预采 |

#### 步骤 B：按需触发采集（未触发则跳过并记账）

| 触发条件 | 采集项 | 未触发时 |
| -------- | ------ | -------- |
| 有表/持久化 | **表数据量**（强制询问，不估算、不默认） | 整段跳过 |
| 有 HTTP 读 | 核心 HTTP 读清单 → 各接口**读峰值** | 跳过接口读峰值 |
| 有 HTTP 写 | 核心 HTTP 写清单 → 各接口**写峰值** + 是否热点 | 跳过接口写峰值 |
| 存在「明显需要」的非接口项 | 核心非接口项清单（方法\|流程）→ 按类型采形态/强度或流程假设 | 第二轴整段跳过（记「无明显非接口并发诉求」） |
| 任一轴有核心项，或涉及锁/缓存/限流/多实例互斥 | **部署形态**（默认预选「集群多实例」，须确认） | 可不采 |
| 用户已确认的核心 HTTP 清单**非空** | **P99**（强制问） | 无核心 HTTP 则跳过 P99；第二轴默认不问 P99 |
| spec **已写明**某策略 | 仅对该策略问是否允许 | 未写明则不问 |

**跳过 ≠ 默认填档**：audit 须写明「已采集 / 已跳过（原因）」。

**采集顺序**：先确认第一轴 HTTP 清单与第二轴非接口清单（均可空）→ 再分轴采档 → 部署/表量/允许策略。

#### 步骤 C1：第一轴 · 核心 HTTP 接口

- 对象**仅** HTTP 接口；不对全量路由逐个问。
- Agent 给候选 + 入选理由 → 用户确认/增删 → 再采峰值。
- 上限：核心读 **≤3**，核心写 **≤3**。
- **优先入选**：C 端/开放、首页/高频列表、关键写（事务/跨边界编排/幂等）、热点行冲突风险。
- **通常不入选**：低频后台 CRUD、按 ID 详情、配置类、常规补偿/运维、一次性迁移。
- 筛空：记「无核心 HTTP，跳过接口峰值与接口星级」。

#### 步骤 C2：第二轴 · 核心非接口项（方法或流程）

- 对象：**(a) 方法** 或 **(b) 整段流程/能力设计**；合计上限 **≤5**；**宁缺毋滥**。
- Agent 必须写清「为何明显需要」；说不清则不入选；用户确认后再采。
- Kafka/cron 的**处理函数**或**整段消费/定时管道**属本轴，**禁止**并入第一轴。

**明显需要（入选信号，须有 spec 证据，满足其一即可候选）**：

- 共享可变状态 / 包级缓存 / 热点 key 或行
- 锁、幂等、限流、多实例抢执行
- 可能重叠的高吞吐消费/定时，或与积压/吞吐相关的管道
- 方法或流程内可能无界扇出 线程/@Async/worker
- 本库能力方案中作为并发安全契约的导出面或能力流程

**默认不入选**：

- 纯转换、`MustInit*`、一次性装配/Close
- 仅被单个 HTTP 串行调用、无共享状态的内部 Service/Repo 步骤（并发算在第一轴）
- 低频单次任务、无重叠/性能诉求的管理流程
- 常规补偿（除非 spec 写明高并发重试）

筛空：记「无明显非接口并发项，跳过第二轴」。

#### 步骤 D：字段规则与选项

**第一轴（HTTP）**：

| 字段 | 规则 | 选项 |
| ---- | ---- | ---- |
| 读/写峰值 | 可估则估+依据并供确认；置信不足禁止预填；确认前不得写入 audit §0 为已确认 | `<10` / `10–100` / `100–1k` / `>1k` QPS |
| 写热点 | 随写峰值 | `有热点` / `无热点` / `不确定` |
| P99 | 有核心 HTTP 时强制问 | `无明确要求（按后台可接受）` / `<50ms` / `<100ms` / `<200ms` / `其他（须手填）` |

**第二轴（方法 | 流程）**：

| 字段 | 适用 | 选项 |
| ---- | ---- | ---- |
| 项类型 | 每项必填 | `方法` / `流程` |
| 调用形态 | 方法 | 单 线程/@Async / 同进程多 线程/@Async / 多实例同时调（可多选） |
| 强度 | 方法 | 低 / 中 / 高（或调用方量级档）；不够信只问不填 |
| 热点 | 方法 | 同一 key/资源：有 / 无 / 不确定 |
| 并发契约 | 方法 | 可并发 / 须外部串行 / 须每实例互斥 |
| 流程假设 | 流程 | 多实例是否重叠；分片/抢占；步骤幂等与顺序；背压；流程级互斥位置（选择或短填，禁止猜测冒充确认） |
| P99 | 第二轴 | **默认不问** |

**共用**：

| 字段 | 规则 | 选项 |
| ---- | ---- | ---- |
| 部署 | 默认预选多实例；预选 ≠ 已确认 | `单实例` / `集群多实例（默认）` |
| 表数据量 | 有表才问 | `<1万` / `1万–100万` / `>100万` |
| 允许策略 | 仅 spec 已写明项 | 每项：`允许` / `不允许` / `待定` |

**HTTP 峰值高置信估算门槛**（须能引用 spec/PRD/仓内容量说明，否则只问不估）：文档已写明量级；或明确低频人工后台且无开放/大批量风险。

#### 步骤 E：采集 UI（强制 AskQuestion）

有适用采集项时，阶段 0 **必须**调用会话内置工具 `AskQuestion` 弹出选择框，等待用户提交后再进入阶段 1。

**工具定位（禁止误判为「没有」）**：

- `AskQuestion` 与 `Read`/`Grep` 同级，是会话内置工具，**不在** MCP / `GetDynamicTools` 目录中。
- **禁止**因动态工具目录搜不到该名，就改用纯文本问卷。
- 未调用 `AskQuestion`（有适用项时）视为阶段 0 **未完成**，不得交付 audit 终稿、不得打星。

**调用要求**：

- 用 `AskQuestion` 一次抛出本轮适用题（可多题）；选项与步骤 D 档位一致。
- 建议拆题：① 确认/增删核心清单；② 第一轴各 HTTP 峰值/热点（若有）；③ 第二轴各方法/流程的形态·强度·契约或流程假设（若有）；④ 部署；⑤ 表量（有表时）；⑥ P99（有核心 HTTP 时）；⑦ 允许策略（仅 spec 已写明）。
- 推荐项放选项第一位，并在 label 末标「（推荐）」；用户仍可改选。
- 清单确认题的选项须含：按建议确认 / 增删后确认（Other）/ 本轴全部跳过。

**回退（唯一例外）**：仅当 **已经调用** `AskQuestion` 且运行时报错或被拒绝后，才允许改用对话模板；须在 audit §0 写明失败原因。不得未调用就回退。回退模板：

```text
【显化审核 · 阶段 0 并发与规模采集】（AskQuestion 失败回退）
- AskQuestion 失败原因：…
- 能力画像：{有表/有 HTTP/有非接口候选/…}
【第一轴 · 接口并发】
- 核心 HTTP 读：… → 各峰值
- 核心 HTTP 写：… → 各峰值/热点
- P99：（有核心 HTTP 时）…
【第二轴 · 非接口并发】
- 核心项（方法|流程，≤5）：…
  - {名} 类型：方法|流程；{形态/强度/热点/契约 或 流程假设}
【共用】
- 部署：集群多实例（默认）| 单实例
- 表数据量（有表时强制）：…
- 允许策略（仅 spec 已写明）：…
- 已跳过：{项 + 原因}
- 已确认：（待用户确认 / 是）
```

#### 步骤 F：阶段 0 产出

写入 **audit.md §0**：能力画像；第一轴清单与峰值/P99；第二轴清单（方法|流程）与假设；部署、表量、允许策略；已跳过原因。**不回写 `spec.md`。**
