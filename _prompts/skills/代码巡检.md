# 代码巡检

---

## 0. 基础信息

- **Skill 名称**: 代码巡检
- **描述**: 对 **yomi-boot-java** 基础库或 **业务 Java 工程** 执行多维代码巡检，输出问题清单与 `_ipc-doc` 报告；本母版不含前端规程
- **作者**: zwei
- **创建日期**: 2026-04-16（2026-10-10 Java 合并重写）

---

## 关联知识库

- **执行前必读**：`knowledge/Java数据访问规范.md`、`knowledge/Java事务与一致性规范.md`、`knowledge/JavaWeb与API规范.md`、`knowledge/基础库能力索引.md`
- **按需**：`knowledge/数据库表设计规范.md`、`knowledge/Redis设计规范.md`

## 1. 目标

- **做什么**：对指定 Java 代码范围执行多维度巡检——分层（Controller/UseCase/DomainService/DomainRepository）、数据访问、事务与幂等、Web/Response、鉴权、事件与消息、Redis、表设计引用、注释等；输出问题清单或在用户授权下修复。
- **为什么**：统一巡检口径，降低崩溃、阻塞、死锁与契约破坏风险。
- **不做什么**：不涉及前端；不做压测与渗透；不把 OpenSpec/SDD 混入输入。

## 3. 技术方案

### 3.1 巡检流程

```text
开始
  ↓
1. 确认范围与是否允许修复
  ↓
2. 按 §3.2 维度检查（读 §2.2 知识文档）
  ↓
3. 问题分级（§3.8）；每包 1～5 星（command 审查标准）
  ↓
4. 落盘 _ipc-doc/...-ipc.md（§3.9）
  ↓
5. 若修复：mvn test / 编译验证
  ↓
结束
```

### 3.2 巡检维度

| 维度 | 核心检查 |
| ---- | -------- |
| 分层架构 | Controller 只调 UseCase；本库经 DomainService 链；写路径默认 `@Transactional` 在 `*UseCase#execute`；领域内按需 DomainServiceImpl（与 spec 一致） |
| 基础库 | 对照能力索引，禁止重复封装 |
| 数据访问 | 参数化 SQL、N+1、无界查询 |
| 事务与幂等 | `@Transactional` 位置；`IdempotencyUtils`（幂等唯一入口）使用 |
| Web/API | 统一 `Response`；`GlobalExceptionAdvice` |
| 鉴权 | token/rbac 配置与路径放行 |
| Redis/Kafka/Event | 键前缀、监听器异常、消费幂等 |
| 注释与可维护性 | 公共 API JavaDoc |

### 3.3 分层架构巡检

| 检查项 | 检查内容 | 依据 |
| ------ | -------- | ---- |
| 模块边界 | 业务逻辑不在 boot component 内 | 基础库能力索引 |
| 依赖 | 业务依赖 core + 按需 component | 基础库能力索引 |
| Controller | 仅协议适配与校验 | JavaWeb与API规范 §3 |
| UseCase | 在 domain 之上；对外统一 **`execute`**；写路径默认 **`@Transactional` 在 `execute`**；编排多个 DomainService；**禁止**互注 UseCase；复用 **`*Helper`**（无 `@Transactional`） | Java事务与一致性规范 §2 |
| DomainService / DomainRepositoryImpl | 领域规则 vs 持久化 | Java数据访问规范 §4 |

**yomi-boot-java 根目录额外检查**（巡检 component 时）：

| 检查项 | 检查内容 |
| ------ | -------- |
| AutoConfiguration | `@ConditionalOnProperty` 与 `yomi.*.enabled` 一致 |
| 公开 API | Properties 校验、无业务域泄漏 |
| 依赖 | 不重复引入已封装三方客户端 |
| SQL | 平台 DDL 仅在 `component-*/sql/` |

### 3.4 数据访问巡检

| 检查项 | 检查内容 | 依据 |
| ------ | -------- | ---- |
| SQL 安全 | 禁止拼接用户输入 | Java数据访问规范 §7 |
| Mapper 作用域 | 不暴露给 Controller | Java数据访问规范 §4 |
| 审计/软删 | 与表设计一致 | 数据库表设计规范 |

### 3.5 事务与幂等巡检

| 检查项 | 检查内容 | 依据 |
| ------ | -------- | ---- |
| 事务入口 | 写路径默认 `*UseCase#execute`；领域内/被调方按需 `DomainServiceImpl`（非 Controller） | Java事务与一致性规范 §2 |
| 跨边界 | 无假分布式 DB 事务 | Java事务与一致性规范 §5 |
| 幂等 | 写接口是否使用 idempotency 组件 | Java事务与一致性规范 §4 |
| 幂等事务 | 幂等调用是否有事务边界（调用点 `@Transactional`，或把模板传给 `IdempotencyUtils`）；记录库是否跟事务一致（附加库要先注册）；闭包内是否又开了 REQUIRES_NEW | Java事务与一致性规范 §4 |

### 3.6 Web 与异常巡检

| 检查项 | 检查内容 | 依据 |
| ------ | -------- | ---- |
| 响应体 | 使用 `Response` / `PageResponse` | JavaWeb与API规范 §2 |
| 业务错误 | `BizException` + `errorCode` | JavaWeb与API规范 §2 |

### 3.7 Redis 设计巡检

| 检查项 | 检查内容 | 依据 |
| ------ | -------- | ---- |
| Key 命名 | 模块前缀、与 `yomi.*` 配置一致 | Redis设计规范 |

### 3.8 问题分级

| 级别 | 说明 |
| ---- | ---- |
| 🔴 严重 | NPE/泄漏/死锁/数据损坏/违反契约 |
| 🟡 警告 | 可维护性、一致性问题 |
| 🔵 建议 | 优化项；架构建议（不计入丢星，见 command） |

### 3.9 报告落盘

| 场景 | 输出路径 |

报告须含：范围、分包星级、问题清单（级别/位置/依据/建议）、综合评估。
