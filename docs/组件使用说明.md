# YomiBoot-Java 组件使用说明

本文说明各 **可选组件** 的 Maven 依赖、中间件前置、配置开关、典型用法与 quick-starter 验证方式。

业务工程通常依赖 `yomi-boot-java-core`，再按需引入 `yomi-boot-java-component-*` 子模块。更完整的工程介绍见 [README.md](../README.md)。

---

## 1. 分层与引入方式

| 模块 | 说明 |
|------|------|
| `yomi-boot-java-base` | 无 Spring 依赖：工具、通用模型、异常 |
| `yomi-boot-java-core` | Web 启动、全局异常、CORS、XSS、BCrypt、雪花 ID、Actuator/Tracing 等；**同样带 `META-INF/spring/...AutoConfiguration.imports`**，无需扫描 `com.yomi` |
| `yomi-boot-java-component-*` | 可插拔能力，**均带 `META-INF/spring/...AutoConfiguration.imports`**（kafka 模块本身是纯静态工具，其装配类只做启动期自检），**无需扫描 `com.yomi`**（宿主继续扫描也不冲突，同名 Bean 以宿主优先）；**自带 Mapper 的组件（ds 之外的 rbac / event / httplog / idempotency）由各自自动配置类 `@MapperScan` 自己的 `repository.mapper` 包，宿主 `@MapperScan` 只扫业务自己的包** |

业务 `pom.xml` 示例（按需删减）：

```xml
<dependency>
    <groupId>com.yomi</groupId>
    <artifactId>yomi-boot-java-core</artifactId>
</dependency>
<dependency>
    <groupId>com.yomi</groupId>
    <artifactId>yomi-boot-java-component-ds</artifactId>
</dependency>
<dependency>
    <groupId>com.yomi</groupId>
    <artifactId>yomi-boot-java-component-redis</artifactId>
</dependency>
```

版本由根工程 `dependencyManagement` 统一管理（当前 `${project.version}`）。

## 3. 能力选型（避免混用）

| 场景 | 推荐 |
|------|------|
| HTTP/接口重复提交、同键返回同一结果 | `component-idempotency`（`@Idempotent` / `IdempotencyUtils`） |
| 消息消费去重、与 Kafka 偏移提交联动 | `component-event` 的 `EventInboxGuard` / `EventUtils.onMessage` |
| 临界区、互斥、单飞 | `component-redis` 的 `LockUtils` |
| 接口 QPS | `component-redis` 的 `@RequestLimit`（需配置 `yomi.ratelimit`） |
| 登录会话 | `component-token` 的 `ITokenService` |
| 图形验证码（人机校验） | `component-captcha` 的 `ICaptchaService` / `CaptchaUtils`（**接口由业务自行封装**） |
| 接口/菜单权限 | `component-rbac`（依赖 token 取 `userId`） |
| 可靠发 Kafka | `component-event` 发件箱 + `component-kafka` 发送 |
| 集群内周期轮询（抢锁、单实例执行） | `component-roundrobin`（`@RoundRobinTask` 或组件内注册任务） |
| 日志/出参脱敏（手机号、身份证等） | `component-desensitize` 的 `IDesensitizeService`（无中间件依赖） |
| HTTP 请求日志异步入库（头/体/响应全采） | `component-httplog`（memory/redis/kafka 三模式，脱敏对接 desensitize；**允许有界丢失**） |
| Cron / 任务平台 | 业务自行 `@Scheduled`、Quartz 或 XXL-JOB（本仓库不封装） |

## 4. 各组件说明

### 4.1 ds（`yomi-boot-java-component-ds`）

- **作用**：dynamic-datasource + MyBatis-Plus；`MyBatisDao`、`BaseEntity` 等。
- **前置**：MySQL / PostgreSQL（组件只针对这两类库维护两套 DDL 与双库通用 SQL）；`spring.datasource.dynamic.*`。
- **建表**：组件依赖的表启用后**启动期自动初始化**——逐表探活（`SELECT 1 FROM t WHERE 1 = 0`），缺表时按当前数据库（`getDatabaseProductName()` 识别 MySQL / PostgreSQL）执行组件 jar 内对应方言脚本 `sql/mysql/xxx.sql` 或 `sql/pgsql/xxx.sql` 自动建表；表已齐全时不做任何 DDL。脚本缺失、执行失败、方言不支持（非 MySQL/PG）或建表后仍缺表才 fail-fast，错误点名缺失的表与脚本路径；所有单例就绪后执行一次（早于 Web 对外服务）。
- **Instant 写库**：内置 `InstantJdbcTypeHandler`（`setTimestamp(Timestamp.from(...))`）覆盖 MyBatis 内置 `InstantTypeHandler`（后者 `setObject(Instant)` 在 PG 驱动直接报"无法推测 SQL 类型"，MySQL 驱动支持）；MySQL / PostgreSQL 行为一致，随组件强制生效、无开关。DDL 侧时间列 MySQL 用 `datetime(3)`（会话固定 UTC）、PostgreSQL 用 `timestamptz(3)`。
- **切库到 PostgreSQL**：依赖里 `org.postgresql:postgresql` 随 ds 提供，只要把 `spring.datasource.dynamic.datasource.*` 的 `url` 换成 `jdbc:postgresql://host:5432/db`、`driver-class-name: org.postgresql.Driver` 即可；`timestamptz(3)` 是瞬时语义，**无需**像 MySQL 那样在 URL 上固定会话时区。
- **拦截器链**：默认内置两项——分页（会改写 SQL，排在前）+ `BlockAttackInnerInterceptor`（防无有效条件的全表 UPDATE/DELETE；确需全表操作可在 Mapper 方法标 `@InterceptorIgnore(blockAttack = "true")` 豁免）；**宿主注册的 `InnerInterceptor` Bean 会被自动收进链**（MP 自带组装因本组件存在恒让位，不收集就会被静默忽略），同类拦截器自动跳过防重复执行；要完全自定义就定义自己的 `MybatisPlusInterceptor` Bean（本组件整体让位）。
- **分页方言**：默认**按当前连接自动探测**（多数据源/多方言各自正确，不必配置）；确定性优先可用 `yomi.boot.ds.pagination.db-type`（如 `POSTGRE_SQL`）显式指定，非法值启动期报错。分页与防全表写**随 ds 组件强制生效、无开关可关**（不存在"只关分页、保留防全表"的组合）；确要自行管理就定义自己的 `MybatisPlusInterceptor` Bean（本组件整体让位，分页与防全表写随之由宿主负责）。
- **SQL**：业务表自建；quick-starter 示例见 `yomi-boot-java-qucik-starter/sql/mysql/test_table.sql` 与 `sql/pgsql/test_table.sql`（组件表无需手工执行）。
- **验证**：`GET /test/ds/test-table/dao`、`/xml` → `TestTableFlowApiTest`。

### 4.2 redis（`yomi-boot-java-component-redis`）

- **作用**：`RedisUtils`、`LockUtils`、Bloom/Stream 等；`@RequestLimit` 限流。
- **前置**：`spring.data.redis.*` 的**连接目标**（`host` / `url` / `sentinel.master|nodes` / `cluster.nodes` / `masterreplica.nodes` 任一）——组件按"指向了实际 Redis"激活：url/sentinel/cluster 写法都能装配；什么目标都不配时组件保持不激活（Boot 的默认 localhost 工厂不会误触发）。
- **Redisson**：目标拓扑从 Boot 的连接信息自动映射（单机/哨兵/集群、`rediss://` 随 SslBundle）；宿主可自定义 `RedissonClient` Bean 覆盖；不支持主从（masterreplica）形态的自动映射，需自定义覆盖（启动报错会点名）。
- **模板**：`StringRedisTemplate` 用 Boot 自动配置的；组件提供 Jackson 序列化的 `CommonRedisTemplate`（Bean 名 `commonRedisTemplate`）。
- **配置**：设置非空 `yomi.ratelimit` 作为**开关 + 键前缀**（例：`yomi:ratelimit:${spring.application.name}:`）。
- **注意**：Redisson 锁为**可重入**；演示/测试「抢锁失败」须在**不同线程**持锁时再 `tryLock`。
- **Stream 消费语义（至少一次，handler 必须幂等）**：`StreamRedisSupport.listen` 的消息会进入消费组 PEL——handler 正常返回立即 XACK；抛异常则记 ERROR 并**不 ACK**（消息留在 PEL，不会丢），用 `claimAndRedeliver(stream, group, consumer, minIdle, handler)` 定时认领重投（可挂 roundrobin）；Redis 抖动/处理异常**不会取消订阅**；同组多实例须用各不相同的 consumerName。
- **验证**：`POST /test/ds/test-redis/flow` → `TestRedisFlowApiTest`。

### 4.3 kafka（`yomi-boot-java-component-kafka`）

- **作用**：`KafkaUtils.sync()` / `async()` 链式发送。
- **前置**：`spring.kafka.*`。
- **说明**：消费侧由业务 `@KafkaListener` 编写；与可靠投递组合时使用 `component-event`。
- **多个 KafkaTemplate**：存在多个模板且无 `@Primary` 时，启动期打 WARN（不指定 beanName 的默认发送会在发送时失败）；用 `KafkaUtils.sync().template(beanName)` 指定，或给其中一个加 `@Primary`。event 发布侧对这一点是**启动期强校验**（配了 `yomi.event.kafka-template-bean-name` 会校验其存在，未配则要求候选唯一或 @Primary）。
- **验证**：`POST /test/ds/test-kafka/flow`（Topic `yomi.test.kafka.demo`）→ `TestKafkaFlowApiTest`。

### 4.4 token（`yomi-boot-java-component-token`）

- **作用**：不透明令牌 + Redis 会话；`ITokenService`（签发、校验、撤销、按用户踢下线）。
- **前置**：Redis。
- **配置**：`yomi.token.enabled=true`（默认 false）；`ttl`、`allow-multi-login`、`store-prefix`、`skip-validate-paths` 等。
- **Web**：`TokenInterceptor` 校验令牌；放行路径用 `skip-validate-paths`。**拦截器/异常处理/WebMvc 配置三个 Bean 只在 Servlet 应用注册**（WebFlux/非 Web 应用只装配 `ITokenService`，避免给出"校验在生效"的错误印象）。
  **错误转发（`/error`）已由拦截器按分发类型（`DispatcherType.ERROR`）自动放行**——404/500 保留真实状态，`skip-validate-paths` 无需再列 `/error`（示例工程已移除该冗余项）；rbac 拦截器同样处理。
- **错误码语义**：缺令牌（`TOKEN_REQUIRED`）与令牌无效（`TOKEN_INVALID`）为 **401**，客户端应清 token 重新登录；校验过程基础设施异常（如 Redis 不可用）为 `TOKEN_VALIDATE_FAILED` + **500**——前端不要据此清 token、监控也不计入"掉线"。
- **滑动续期**：`renew-on-validate=true` 时按 `ttl` 续期，**受 `max-lifetime`（默认 1 天）绝对上限约束**，到上限需重新登录；续期写回带原子守卫，会话已注销/被踢时不写回、不复活。
- **验证**：`POST /test/ds/test-token/flow` → `TestTokenFlowApiTest`（与 rbac 演示独立）。

### 4.5 rbac（`yomi-boot-java-component-rbac`）

- **作用**：权限模型（角色/权限/分组）+ HTTP 鉴权拦截器；可选 Redis 投影加速。
- **前置**：MySQL / PostgreSQL、Redis、token 已启用。
- **配置**：`yomi.rbac.enabled=true`；`skip-authorize-paths`；`projection-enabled` 等。
- **权限路径匹配**：API 权限 `http-path` 支持 Ant 风格通配——`*` 单段、`**` 多段、`{var}` 单段变量（例：`/api/user/**`、`/api/user/{id}`）；精确相等优先；投影与 SQL 两种模式语义一致。路径口径由 `http-path-style`（默认 `REQUEST_URI`）决定。**带 context-path 的部署无需特殊处理**：按 `REQUEST_URI` 原样匹配被拒后，会自动去掉 context-path 再匹配一次（两种登记方式都兼容）。
- **错误码语义**：确实没有权限 → `RBAC_FORBIDDEN`（403）；校验过程本身失败（基础设施异常等）→ `RBAC_EVAL_FAILED`（**500**）——前端不要把它当"无权限"，监控也不会把系统故障计成越权。
- **内置角色状态**：语义是"必须始终启用"——"启用"请求幂等；若状态被 DB 误改为禁用，调该 API 即可恢复（会打 WARN）；"禁用"始终被拒（`RBAC_BUILTIN_IMMUTABLE`）。
- **投影完整性**：版本按"指针行数 vs 实际读到行数"校验，半截版本（刷新删旧版本/内存淘汰/坏字段）一律视为不可读并**自动回源 DB**，不会被当成完整快照；id 索引按快照缓存，不随请求重建。
- **删除约定**：RBAC 统一**物理删除**——删除角色连带清理"角色-权限组""用户-角色"绑定，编码删除后可复用；存量库若遗留历史软删行（占 `uk_code`），按 sql 文件头部注释的清理 SQL 处理一次。
- **Redis 故障降级**：投影读取失败/回源写回失败时自动退化为"仅查 DB + 内存缓存（memTtl）"，读路径可用性不依赖 Redis，不会把基础设施故障穿透成 403。
- **SQL**：`yomi-boot-java-component-rbac/sql/mysql|pgsql/sys_rbac.sql`（两方言目录，含内置超管种子）。
- **建表**：启用后启动期自动建表——缺表时按当前数据库执行对应方言脚本（含内置超管种子）；脚本缺失/执行失败/建表后仍缺表才 fail-fast，报错点名缺失的表与脚本路径。存量库升级（表已有但结构旧）需手工 `ALTER`，脚本头部注释给出增量语句。
- **服务出入参模型**：管理/授权服务**不暴露表实体**——权限/权限组/角色统一返回 `RbacPermModel`/`RbacPermGroupModel`/`RbacRoleModel`（model 包；列表基础字段，详情额外含绑定关系ID），查询入参为 `RbacPermQuery`/`RbacPermGroupQuery`/`RbacRoleQuery`（model 包，继承 `PageRequest`）；实体 → 视图模型的映射集中在 `convert.RbacModelConverter`（模型类只保留数据）。
- **分页约定**：管理服务分页接口统一使用 base 的 `PageRequest`（入参：`pageNo` 从 1 起、默认每页 10、上限 500）与 `PageResponse`（出参）；`RbacPermQuery`/`RbacPermGroupQuery`/`RbacRoleQuery` 继承 `PageRequest`，MP `Page` 仅出现在仓储内部。
- **验证**：`GET /test/ds/test-rbac/flow`、`issue-token`、`whoami`；受保护接口 `/test/rbac/protected` → `TestRbacFlowApiTest`。

### 4.6 idempotency（`yomi-boot-java-component-idempotency`）

- **作用**：方法级幂等；`@Idempotent`、`IdempotencyUtils`。
- **前置**：MySQL / PostgreSQL、Redis；roundrobin 用于清理僵死「处理中」记录。
- **配置**：`yomi.idempotency.enabled=true`；`store-prefix`、`result-cache-ttl`、`record-retention` 等。
- **SQL**：`yomi-boot-java-component-idempotency/sql/mysql|pgsql/sys_idempotency_record.sql`。
- **建表**：启用后启动期自动建表——缺表时按当前数据库执行对应方言脚本；脚本缺失/执行失败/建表后仍缺表才 fail-fast。
- **降级与类型**：
  - **Redis 不可用时自动降级为无锁 + DB 唯一键兜底**（fail-open，不再让所有幂等接口 500）：分布式锁只是"省一次 DB 写入"的优化，互斥由 `(namespace, idempotency_key)` 唯一键 + 事务内先插占位承担。
  - **泛型返回值重放不丢里层类型**：`@Idempotent` 方法返回 `Result<T>`/`List<T>` 时，重复请求原样还原；编程式调用可用 `IdempotencyUtils.execute(..., Type, ...)` 传入完整泛型（如 `new TypeReference<Result<OrderVO>>(){}.getType()`）。
  - **接口返回类型变更后**，旧记录重放会报 `IDEMPOTENCY_RESULT_TYPE_MISMATCH` 而不是静默返回结构不符的对象（需更换幂等键或清理旧记录）。
  - **幂等 key 由调用方决定**（默认不含用户/租户维度，保持灵活性）：需要按用户隔离时请在 key 表达式里带上用户标识，避免客户端复用同一 key 造成跨用户重放。
  - **PG 事务中毒防护（保存点）**：占位 INSERT 用保存点（`SavepointScope`）包住——PostgreSQL 里唯一键冲突会把整个事务打成 aborted（后续语句一律 25P02），冲突后必须先回滚到保存点才能读回已完成结果；MySQL 无此限制，行为不变，保存点两边通用。事务管理器不支持保存点时自动退化为不建保存点（MySQL 不受影响）。
- **验证**：`POST /test/ds/test-idempotency/annotation`、`/utils`（可选参数 `flowKey` 指定幂等键；删除 Redis 结果键后用同一 `flowKey` 再调，即走"缓存冷 + 库中已有记录"的冲突读回路径）→ `TestIdempotencyFlowApiTest`。

### 4.7 event（`yomi-boot-java-component-event`）

- **作用**：Transactional Outbox 写库 + RoundRobin 抓取 + Kafka 投递；消费侧 `EventUtils` + Inbox 幂等。
- **前置**：MySQL / PostgreSQL、Redis、Kafka、`yomi.roundrobin.enabled=true`（发布中继、DLQ 重试、保留期清理都由轮询任务调度；开关开启而 RoundRobin 不可用时**启动即失败**，不静默）。
- **配置**：`yomi.event.publisher-enabled` / `consumer-enabled`；发件箱轮询、批次、DLQ 等见 `EventProperties`（前缀 `yomi.event`）。
- **eventId 唯一性**：自定义 `eventId` 必须在**同一 topic 的所有生产者之间唯一**（消费侧幂等键是 `service_name + eventId`，跨生产者撞 id 的消息会被当作重复静默跳过、不执行业务）；不确定时用 `EventUtils.newEventId()`。
- **SQL**：`yomi-boot-java-component-event/sql/mysql|pgsql/sys_event.sql`。
- **建表**：启动期自动建表——publisher 侧探活发件箱 + DLQ、consumer 侧探活收件箱，缺表时按当前数据库执行对应方言脚本（脚本含该组件全部 3 张表，故缺任意一张即整脚本执行一次，可能顺带创建尚无需要的兄弟表）；脚本缺失/执行失败/建表后仍缺表才 fail-fast。
- **保留期清理（默认关闭，表默认只增不删）**：`yomi.event.retention.enabled=true` 后，发件箱按 `outbox-retention`（默认 14 天）删除 `SENT_SUCCESS` 且 `sent_time` 超期的行；
  收件箱需再开 `retention.inbox-retention-enabled=true`——收件箱行是"只消费一次"的依据，**保留期必须 ≥ 事件可能被重投的最长时间（Kafka topic retention，默认 7 天）**，否则超期重投会被当新消息再消费一次（配 <1 天启动报错、<7 天启动告警）；
  间隔 `retention.scan-interval`（默认 1 小时）、`batch-size`、`max-delete-per-run`；索引：inbox 已有 `idx_create_time`，outbox 已内置 `idx_status_sent_time`（老库升级需手工 `ALTER TABLE ... ADD KEY idx_status_sent_time (status, sent_time)`，见 sql 文件注释）。
  清理任务由 RoundRobin 调度：开启 `inbox-retention-enabled` 而 RoundRobin 不可用时**启动失败**；仅消费侧启用且未开收件箱清理时启动 WARN 提示"不会注册任何清理任务"（发件箱清理随 publisher 生效）。
- **消费语义（重要）**：消费返回 `RETRY` 时必须在 retry 动作里**显式退回重投**（如 `acknowledgment.nack(...)`）。
  仅"不提交 offset"不会让 Kafka 重投——manual ack 模式下提交的是已确认的最大 offset+1，同分区后续消息一旦提交，
  失败那条就被永久跳过（参考 `TestEventDemoKafkaListener`）。毒消息会无限 nack 循环并阻塞该分区，
  这是"至少一次"的固有代价；需要"有限重试 + 死信"的接入方请改用抛异常 + `DefaultErrorHandler`（可配 `DeadLetterPublishRecoverer`）。
  **Redis 故障时消费降级为无锁路径（WARN）**：分布式锁只是"省一次写库"的优化，互斥由 inbox 唯一键承担，消息不会在 Redis 故障期间被全部卡在 RETRY。
  **并发插入撞唯一键时按重复消息跳过**（业务不再执行），并把 inbox INSERT 包在保存点里：PG 下冲突会让事务 aborted，回滚保存点后本次事务照常提交，不会把同事务的其它写入一起带走（MySQL 行为不变）。
- **业务接入（查询/运维服务）**：根包 `IEventService`（实现 `service.EventService`）——查询：`outboxStatus(eventId)` / `findOutbox(eventId)`（含 payload）/ `pageOutbox`（概要分页，按状态/topic/时间）/ `pageDlq`（含关联 eventId 与失败原因）/ `consumed(eventId)`（消费凭证）；操作：`requeue(eventId)`（未送达事件重置 PENDING 并删除其 DLQ 由中继重投——**至少一次**语义、消费端幂等兜底，已 SENT_SUCCESS 拒绝重发）与 `resetDlqRetryCount(from,to)`（人工恢复自动重试）。数据一律按当前服务隔离；能力未启用时调用抛带配置指引的异常；实体 → 视图模型的映射集中在 `convert.EventModelConverter`（模型类只保留数据）。
- **验证**：
  - 不依赖 Kafka：`POST /test/ds/test-event/utils-flow` → `TestEventFlowApiTest`。
  - 端到端 Kafka：需启用 publisher、配置 broker，并注册 `@KafkaListener`（参考 quick-starter `TestEventDemoKafkaListener`）。

### 4.8 roundrobin（`yomi-boot-java-component-roundrobin`）

- **作用**：多实例下按任务名抢锁，周期执行；支持 `@RoundRobinTask` 声明式任务。
- **前置**：Redis。
- **配置**：`yomi.roundrobin.enabled=true`；`store-prefix`。
- **任务简介（`description`）**：`@RoundRobinTask(description = "...")`（组件内注册的任务由注册方传入）。启动时每个任务打一行 `RoundRobin[任务名] 生效配置: description=..., frequency=...`，**未填写打印 `description=未填写`**——运维只看到任务名时无从判断它在做什么。
- **执行锁租约（`exec-watchdog` / `exec-lock-ttl`）**：`exec-watchdog=true`（默认）时租约由 Redisson 看门狗续期、**无上限**，`exec-lock-ttl` 不参与锁租约（仅作 `max-hold-duration` 的下限参照，显式配置会启动 WARN）；`exec-watchdog=false` 时 `exec-lock-ttl` 是**硬租约**——任务必须在其内完成，否则锁过期、其它实例可能并发执行同一任务（此时 `max-hold-duration` 必须 ≤ `exec-lock-ttl`，否则启动报错）。**丢锁只在任务运行期间判定**（50ms 存活检测）并记 **ERROR**（含租约值与排查方向）；任务结束后的字段缺失是本轮自己的 `unlock`（解锁与检测的天然竞态），不报；任务耗时短于 50ms 检测周期时检测不触发，由**解锁结果**兜底上报（`释放执行锁时发现锁已易主/被删`），同一事件只记一条。
- **轮询节奏与失败退避**：`frequency` 是**最小间隔**（真实周期 ≈ 任务耗时 + [frequency+randomDelayMin, frequency+randomDelayMax]，默认 = 任务耗时 + [f+100ms, 2f+100ms)），估算延迟请按频率下限算；任务执行失败（含 tick 异常）按**连续失败次数指数退避**（1s→2s→…→60s 封顶，10 次后日志降为 WARN）——下游故障期不会全速空转。
- **调度线程池**：内置专用池（4 线程，承载 50ms 周期的丢锁检测）；**只有宿主显式提供名为 `roundRobinScheduler` 的 Bean 才会顶替**（建议 2+ 线程的小池），普通的同类型 Bean 不再被静默接管；若该池不可用（被关停），任务会跳过本轮并**释放执行锁**（不裸跑、不漏锁），每轮 WARN 提示。
- **`max-hold-duration` 是协作式**：到期只置取消标志并打 WARN，**不强制中断任务、不停止锁续期**——handler 必须轮询 `ctx.isCancelled()` 才有效（`watchdog=false` 时该值必须 ≤ `exec-lock-ttl`，否则启动报错）。
- **与定时任务**：复杂调度用 Spring `@Scheduled` / Quartz / XXL-JOB；roundrobin 适合**高频 tick、与组件 relay 同模式**的后台循环。
- **验证**：`POST /test/ds/test-roundrobin/flow` → `TestRoundRobinFlowApiTest`。

### 4.10 captcha（`yomi-boot-java-component-captcha`）

- **作用**：图形验证码（人机校验）。两种挑战：**读图输入**（`TEXT`）、**看图算数**（`ARITHMETIC`，默认运算符 `+ - ×`）；自带干扰滤镜（干扰线、噪点、波纹）。纯 JDK AWT 绘制，**内嵌 Roboto-Bold v2.138（Apache-2.0，许可全文见模块 `resources/fonts/LICENSE.txt`）**：字形全覆盖（含 `×`）且各环境渲染一致。
- **前置**：无中间件依赖（不配 Redis 也能用）；`store=redis` 时需 **Redis ≥ 6.2**（校验用 GETDEL 一次性取值）。**Linux 镜像需具备可用字体**：实测 JDK 加载自定义字体仍要求系统装有至少一款字体（空字体目录下 `Font.createFont` 直接失败）——官方 JRE 镜像一般自带，精简镜像请装 `fontconfig` + 任一字体系（如 `apt-get install -y fontconfig fonts-dejavu-core`）。缺字体时装配期预热渲染即报错（启动失败）并给出上述提示，不会拖到首个用户请求。
- **组件不提供任何接口**：只给服务与工具方法，接口、响应模型、放行路径、`Cache-Control: no-store` 都由业务自行封装（quick-starter 的 `TestCaptchaFlowController` 是样板）。
- **配置**：`yomi.captcha.enabled=true`（默认 false）、`store`（见下）、`store-prefix`（仅 redis 存储需要）、`ttl`（默认 2m）、`default-type`、`image.*`、`text.*`、`arithmetic.*`、`filter.*`、`local.max-entries`；`log-answer` 仅联调（开启后每次生成打 WARN 且消息自带禁用提示，生产禁止）。改 `text.charset` 时须确保字形被字体覆盖（渲染器装配期对未覆盖字符打 WARN；否则图上画成缺字方块、校验恒不符），且只支持基本平面字符——含 emoji 等增补平面字符（代理对）**启动期即失败**（图片按单字符绘制，画不出、用户也打不出）。
- **存储（`store`）**：`auto`（默认，配了 Redis 用 redis，否则 local）/ `local` / `redis`。显式 `store=redis` 但未配置 Redis **启动即失败**；键前缀只在 redis 存储时解析（未配 `store-prefix` 时按 `spring.application.name` 推导，两者都没有则 `store=redis` 启动失败；local 不落键、不需要这两项）；`store=local` 时**多实例部署会出现 A 实例签发、B 实例校验失败**（装配日志会打印实际存储，部署多实例时请确认是 redis）。
- **调用语义（重要）**：
  - **一次性消费**：`verify` 无论输对输错，挑战即刻失效（防爆破、防重放）；返回三态 `OK`（通过）/ `MISMATCH`（答案不符）/ `EXPIRED`（过期、不存在或已消费）——`MISMATCH` 与 `EXPIRED` 是**正常业务结果**，不是错误。
  - **诚实失败**：存储/渲染等基础设施异常抛 `CaptchaException`（500 + `CAPTCHA_GENERATE_FAILED` / `CAPTCHA_VERIFY_FAILED` / `CAPTCHA_INVALIDATE_FAILED`），不静默放行也不伪装成"输错"；业务要降级放行必须显式 catch。组件内置 `CaptchaExceptionAdvice` 输出该错误码（Servlet 应用；宿主可用同类型 Bean 顶替），**不含任何接口**。
  - 文本类**大小写不敏感**（默认字符集已剔除易混字符 0/O、1/I/L、2/Z、5/S）；算术题结果非负且排除 0/1。
  - 验证必须与业务动作（登录等）在**同一请求内**完成，不要单独暴露 `/verify` 接口（否则该接口本身可被刷）；生成接口建议配 `@RequestLimit` 防止图片生成被刷（组件不含接口，限流归业务侧，见《Redis设计规范》§3.6）。
- **用法**：
  ```java
  // 生成：CaptchaUtils.generate() / generate(CaptchaType.ARITHMETIC)
  CaptchaChallenge challenge = captchaService.generate(null);
  // 下发：challenge.captchaId() + challenge.dataUri()（data URI 可直接给 <img src>；要吐 image/png 用 challenge.png()）
  // 校验（登录接口内）：CaptchaVerifyResult result = captchaService.verify(req.getCaptchaId(), req.getCaptcha());
  ```
- **验证**：`GET /test/ds/test-captcha/generate?type=text|arithmetic`、`POST /test/ds/test-captcha/verify?captchaId=..&answer=..` → `TestCaptchaFlowApiTest`。

### 4.11 desensitize（`yomi-boot-java-component-desensitize`）

- **作用**：脱敏（手机号、身份证、日志/出参等）。门面 `IDesensitizeService.mask(策略名, 值)` 只有一个方法；策略是一条脱敏规则（`DesensitizeStrategy`），**都是 Spring Bean**，策略中心 `DesensitizeStrategyRegistry` 从容器取全部策略实例并按策略名索引。
- **内置策略**：`DesensitizeType` 12 项 —— `ALL`（整体遮蔽，保留长度）、`NAME`、`MOBILE`、`FIXED_PHONE`、`ID_CARD`、`BANK_CARD`、`EMAIL`、`ADDRESS`、`CAR_NO`、`PASSPORT`、`USERNAME`、`PASSWORD`；各策略类集中在 `strategy` 包、带 `@Component` 并由装配类 `@Import` 显式引入（**auto-configuration 按推荐方式不做组件扫描，宿主也无需扫描 `com.yomi`**），规则见各策略类 javadoc。**策略名是普通字符串**，内置枚举只是词表，宿主自定义名称与之无关。
- **自定义策略**：实现 `DesensitizeStrategy`，或继承 `AbstractDesensitizeStrategy`（保前后位的如工号、学号直接继承 / 实例化 `KeepEdgeDesensitizeStrategy`）并声明为 Bean，即自动被策略中心收集。
- **调整规则**：内置策略 Bean **不支持同名替换**——声明与内置同名的 Bean（如 `mobileDesensitizeStrategy`）会**启动即失败**（报错点名冲突的策略名与 Bean）；内置规则不满足时**新增一个策略名**的实现（新 Bean 名 + 新策略名），调用点改用新名称；需要完全自定义策略集合时替换 `DesensitizeStrategyRegistry` Bean（那时不校验内置齐备）。
- **策略名规范（装配期校验）**：**非空 + 全局唯一**，风格不限（内置用 `MOBILE` 这类大写名，自定义命名随意）——null/空白名与重名都在启动期报错并点名牌名与 Bean；另校验 `DesensitizeType` 12 个内置名称齐备（防御性断言，正常装配不可达）。
- **装配**：无配置项、无开关（纯逻辑无中间件依赖，**不引入本组件即关闭**），自动装配、无需扫描 `com.yomi`。策略名未注册直接报错（不静默返回原值）；宿主自行实现 `IDesensitizeService` 并注册 Bean 后默认实现不再装配。
- **约定**：null 返回 null、空串原样返回；按 code point 切分不切断代理对；长度不足以保留前后位数时整体遮蔽；含空格/连字符的输入**按普通字符计位、不自动清洗**（需要先归一化由业务自行处理，或新增一个自定义策略实现）。
- **用法**：

  ```java
  String mobile = desensitizeService.mask(DesensitizeType.MOBILE.name(), "13812345678"); // 138****5678
  String studentNo = desensitizeService.mask("STUDENT_NO", "2024001");                  // 自定义策略名

  // 自定义策略（声明 Bean 即注册）：
  @Component
  public class StudentNoDesensitizeStrategy extends KeepEdgeDesensitizeStrategy {
      public StudentNoDesensitizeStrategy() { super("STUDENT_NO", 4, 2); }
  }
  ```

- **验证**：组件无 Web 层（**无接口**），由模块内 27 个离线用例覆盖（内置规则表 9、策略中心语义 6、装配 9、保前后位策略 3）；quick-starter 已引入依赖，应用启动即装配（日志 `脱敏服务已启用: 策略 12 个: ...`），注入 `IDesensitizeService` 即可用（无演示接口）。

### 4.12 httplog（`yomi-boot-java-component-httplog`）

- **作用**：HTTP 请求日志异步入库；请求头/请求体/响应头/响应体**默认全采**（各 8KB 截断可配），脱敏对接 `component-desensitize`，保留期清理挂 roundrobin。组件不提供任何查询接口。
- **前置**：MySQL / PostgreSQL（表 `sys_http_log`）；`yomi.httplog.enabled=true`；`mode=redis` 需 Redis、`mode=kafka` 需 `spring.kafka.*`——**memory 模式零中间件依赖**。
- **配置**：`mode=memory|redis|kafka`（默认 memory）；`collect.*`（四个 record 开关默认全 true、`max-request/response-body-bytes` 默认 8192**且不得超过 60000**（body 列为 text，超限启动报错）、`exclude-paths`、`body-skip-paths`、降量闸门 `sample-rate`/`min-duration-ms`/`status-threshold`、`trusted-proxies`）；`buffer.*`（容量 4096/批量 1000/`drop-policy`/停机排空超时）；`store.datasource`（空=容器默认数据源；填 ds 名即写入线程编程式切换，`@DS` 在组件线程不生效）；`redis.*`（`structure=list|stream`、`read-count`、`block-ms`、`group`、`consumer-name` 默认主机名）；`kafka.*`（topic/消费组/并发/`template-bean-name`）；`retention.*`（默认开、7 天、roundrobin 两阶段物理删除）。
- **SQL**：`yomi-boot-java-component-httplog/sql/mysql|pgsql/sys_http_log.sql`；启动期自动建表（缺表按当前数据库执行对应方言脚本），脚本缺失/执行失败/建表后仍缺表才 fail-fast。
- **脱敏（关键）**：词表全走配置、**组件零内置词表**——`yomi.httplog.desensitize.key-types`（键名 → 策略名，一条词表作用于请求头/响应头/query/请求体/响应体五处；键名写法宽松匹配：`idCard` ≡ `id_card` ≡ `ID-CARD`，**配什么命中什么**，无包含/通配）；`key-excludes` 排除优先。**空词表启动 WARN 放行（原样入库）**；词表引用**未注册策略名则启动失败**（报错列出已注册名单）。body 结构化脱敏支持 JSON/form（**无命中免重建**；截断体无法解析、原样保留=文档声明的盲区），默认在**后台线程**执行（`in-request-thread=true` 改请求线程）。
- **传输模式与丢失边界（允许有界丢失）**：memory=进程内缓冲直落库（崩溃丢缓冲内/在途批）；redis=**List 结构默认**（`RPUSH` 批量写 / `LPOP count` 批量读，需 Redis ≥ 6.2；`structure=stream` 为消费组变体：无论成败按批 XACK——失败按丢弃计数**不无限重投**，崩溃遗留的 PEL 由同名 consumer（默认主机名，`redis.consumer-name` 可配）重启后补投、不认领其他实例 PEL），pop/XACK 即移位不重复；kafka=topic 中转（按批提交，重复由雪花主键收敛；**topic 不存在时由消费容器持续重试，不做启动期 fail-fast**，生产建议预建 topic）。**无 ACK/DLQ/手动 commit 机制**：落库失败重试 2 次后丢弃并计数（指标 `yomi.httplog.dropped`，正常负载不丢）；`SQLState 23` 完整性冲突逐条隔离按"已写入"跳过。
- **扩展点**：`HttpLogContextEnricher`（声明 Bean 即生效）可填充 `userId`/`errorMsg`；`HttpLogStore` Bean 可整体替换为异构存储。
- **查询接入（业务系统用）**：**根包服务接口 `IHttpLogService`**（默认实现为 `service.HttpLogService`）——`page(HttpLogQuery)` 概要分页（不含头/体大字段）、`get(id)` 全量单条；默认只查当前服务（`allServices=true` 放开），`HttpLogQuery` 可直接作为 Controller 的查询参数对象（时间范围 `@DateTimeFormat` ISO、`minStatus`、`uriLike`、`traceId` 等），分页用 base 的 `PageResponse`；返回内容为**入库时已脱敏值**；数据库操作一律经**仓储端口 `repository.IHttpLogRepository`**（默认实现 `HttpLogRepository`；查询服务/落库/清理均不直连 Mapper，两者均可由宿主实现 Bean 顶替）；演示样板：`GET /test/ds/test-httplog/query`（概要）/ `GET /test/ds/test-httplog/detail?id=`（全量，见 `TestHttpLogFlowController`）；实体 → 视图模型的映射集中在 `convert.HttpLogModelConverter`（模型类只保留数据）。
- **注意**：Filter 仅 Servlet 应用装配；**async 请求在 ASYNC 分发结束时采集**（状态/耗时/响应体都是最终值，`async_started` 标记异步请求；async 线程经包装 writer 写出的内容也随该分发落到底层响应，客户端不丢数据；无 ASYNC 分发的异步异常路径不采集）；multipart/二进制/流式（octet-stream、event-stream、image/audio/video 等）body 不记录（仍完整透传）；全量采集的磁盘量必须评估（启动日志打印公式与估算提示）；操作审计语义由业务自建，本组件是技术向请求日志。
- **验证**：`POST /test/ds/test-httplog/flow?marker=xxx`、GET `/test/ds/test-httplog/async-flow?marker=xxx`（异步分发完整采集）→ `TestHttpLogFlowApiTest`（覆盖五项全采、四类脱敏、宿主自定义策略 `EMPLOYEE_NO`、async 请求最终状态/耗时/响应体端到端）。
