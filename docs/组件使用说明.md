# yomi-boot-java 组件使用说明

按需引入 `yomi-boot-java-component-*`，配好中间件和开关就能用。工程结构、版本管理见 [README.md](../README.md)。

---

## 怎么接

| 模块 | 一句话 |
|------|--------|
| `yomi-boot-java-base` | 工具、通用模型，不依赖 Spring |
| `yomi-boot-java-core` | Web 启动、全局异常、安全与观测等基础能力（业务一般必引） |
| `yomi-boot-java-component-*` | 可选能力，带自动配置，**不用扫 `com.yomi`** |

```xml
<dependency>
    <groupId>com.yomi</groupId>
    <artifactId>yomi-boot-java-core</artifactId>
</dependency>
<!-- 下面按需加 -->
<dependency>
    <groupId>com.yomi</groupId>
    <artifactId>yomi-boot-java-component-ds</artifactId>
</dependency>
```

带自己 Mapper 的组件（rbac / event / httplog / idempotency）会扫自己的 `repository.mapper`；业务 `@MapperScan` 只扫自己的包即可。

| 组件 | 会顺带引入 |
|------|------------|
| ds / redis / kafka / oss / desensitize | core |

| event | core + ds + redis + kafka |
| httplog | core + ds + redis + kafka + desensitize |

## 场景怎么选

| 你想做的事 | 用哪个 |
|------------|--------|
| 接口防重复提交、同 key 返回同一结果 | idempotency |
| Kafka 消费去重 | event（收件箱） |
| 分布式锁、互斥 | redis（`LockUtils`） |
| 接口限流 | redis（`@RequestLimit` + `yomi.ratelimit`） |
| 登录会话 / Token | token |
| 图形验证码 | captcha（**接口自己写**） |
| 菜单 / 接口权限 | rbac |
| 可靠发 Kafka | event + kafka |
| 多实例里「只跑一台」的周期任务 | redis（`ClusterTask`） |
| 手机号、身份证等脱敏 | desensitize |
| HTTP 访问日志落库 | httplog |
| Cron / XXL-JOB 等 | 业务自选，本仓库不包 |

## 各组件

写法统一：**依赖 → 环境 → 开关 → 常用 API → 本地怎么验**。细节以各模块源码与 `*Properties` 为准。

### ds（`yomi-boot-java-component-ds`）

- **干啥**：配好主库后，提供 MyBatis-Plus（分页、防全表误删/误改）、`MyBatisDao`、`BaseEntity` 等。
- **环境**：MySQL 或 PostgreSQL；`spring.datasource.*`。不配数据源时组件不装主库，仍可用部分工具类。
- **开关**：`yomi.ds.preheat.enabled`（数据源预热，默认开）、`yomi.ds.transaction-guard`（跨库访问守卫，`error` 默认 / `off`）、`yomi.ds.pagination.db-type`（固定分页方言，留空自动探测）。
- **注意**：组件表缺了会在启动时按方言自动建；`Instant` 写库、分页已内置。连接池默认 Hikari，可换 `spring.datasource.type`。
- **主库独占**：主库四件套（`masterDataSource` / `masterSqlSessionFactory` / `masterSqlSessionTemplate` / `masterTransactionManager`）只由本组件按 yml 装配，**业务不得声明 `masterXxx`**（声明即启动失败：主数据源只走 `spring.datasource.*`，换池用 `spring.datasource.type`）。
- **多库**：**别的库数据源、工厂、模板、事务你自己建**（用业务自己的 Bean 名、不标 `@Primary`），`@MapperScan` 要写齐 `sqlSessionFactoryRef` 和 `sqlSessionTemplateRef`，附加库事务要指定 `transactionManager`。
- **组件默认走主库**：需要库的组件（rbac / event / idempotency / httplog）的 Mapper、事务、建表都锚在主库上；启动期做绑定审计，不写 ref 的 Mapper 落在别的工厂、附加库那套标了 `@Primary`、事务模板绑别的库——都拦启动。
- **验证**：`GET /test/ds/test-table/dao`、`/xml`

### redis（`yomi-boot-java-component-redis`）

- **干啥**：`RedisUtils`、`LockUtils`、布隆/Stream 等；`@RequestLimit` 限流；`ClusterTask` 集群定时任务（多实例「只跑一台」，组件内部的中继/清理也用它）。
- **环境**：配好 `spring.data.redis.*` 里至少一种连接方式（host/url/哨兵/集群等），否则组件不激活。
- **开关**：限流需非空 `yomi.ratelimit`（兼作 key 前缀）。`@RequestLimit` 写在**实现类方法**上。
- **集群定时任务**：`new ClusterTask(任务名, 间隔, environment, 执行体)`（`Environment` 由 `@Bean` 方法注入）；每任务独占一个单线程调度器、间隔不得小于 50ms，集群每间隔只放行一个实例（Redis `SET NX` 轮次名额、TTL=间隔），上一轮未结束时下一轮跳过（Redisson 执行锁）——多实例里只跑一台。任务名即键名的一部分（`yomi:schedule:{spring.application.name}:turn|lock:{任务名}`，改名等于换键）；执行体异常记 ERROR 后继续下一轮；停机等当前一轮跑完（等待 = min(30s, 阶段停机超时 × 0.8)；阶段停机超时取 Boot 的 `LifecycleProperties`，即 `spring.lifecycle.timeout-per-shutdown-phase` 的生效值——未配置时该默认值只在 Boot 的 properties Bean 里，Environment 里读不到）。复杂定时（cron、长任务编排）用 `@Scheduled` / Quartz / XXL-JOB。
- **验证**：`POST /test/ds/test-redis/flow`；集群定时任务 `POST /test/ds/test-schedule/flow`

### kafka（`yomi-boot-java-component-kafka`）

- **干啥**：`KafkaUtils.sync()` / `async()` 发消息。
- **环境**：`spring.kafka.*`；消费自己写 `@KafkaListener`，要和可靠投递一起看 event。
- **验证**：`POST /test/ds/test-kafka/flow`

### token（`yomi-boot-java-component-token`）

- **干啥**：不透明 Token + Redis 会话，`ITokenService` 签发/校验/踢人。
- **环境**：Redis 必须可用（按连接配置判断，不能只有默认 localhost 模板）。
- **开关**：`yomi.token.enabled=true`（默认关）；`skip-validate-paths` 放行；单点登录相关看 `allow-multi-login`、`ttl`、`max-lifetime`。
- **进程内缓存**：`local-cache-ttl`（默认 `30s`，可配，**`0` = 关闭**）把校验结果按令牌散列缓存——命中时不打 Redis（省掉路由键 + 快照键两次 GET）。**条目 TTL 取 min(本值, 令牌剩余有效期)**，本地条目绝不会比令牌活得久；条目超出固定容量上限会自动淘汰。
- **主动失效（Redis pub/sub）**：通道 `{storePrefix}:invalidate`，一条消息 = 一个令牌散列。撤销 / 踢人 / 单点登录互踢在 Redis 生效后**先清本实例条目、再广播通知**，其它实例收到即清（正常毫秒级）。投递是"至多一次"：订阅连接断开期间的通知会丢，靠条目 TTL 兜底——所以最坏情况下其它实例在 `local-cache-ttl` 内生效。命中缓存后仍会重新校验有效期，过期/失效不会被缓存放大。
- **注意**：缺 Token / 无效 → 401；Redis 挂了校验失败 → 500，别当掉线。Servlet 才有拦截器，WebFlux 只有服务 Bean。
- **验证**：`GET /test/ds/test-rbac/issue-token?userId=1` → `GET /test/ds/test-rbac/whoami?token=` → `GET /test/ds/test-rbac/revoke?token=`（连续两次 whoami 第二次不打 Redis；撤销后立即失效）

### rbac（`yomi-boot-java-component-rbac`）

- **干啥**：角色、权限、分组 + HTTP 鉴权；可选 Redis 投影加速。
- **环境**：主数据源（MySQL/PG）+ Redis + token 已开。
- **开关**：`yomi.rbac.enabled=true`；`skip-authorize-paths` 放行。
- **注意**：真没权限 403；鉴权过程异常 500。管理接口用 `PageRequest` / `PageResponse` 分页。
- **验证**：`GET /test/ds/test-rbac/flow` 等；受保护接口 `/test/rbac/protected`

### idempotency（`yomi-boot-java-component-idempotency`）

- **干啥**：`IdempotencyUtils`（唯一入口，静态方法）做方法级幂等。
- **环境**：主数据源 + Redis；默认只注册主库（自动建表 + 自动清理，清理由集群定时任务驱动）。附加库要用幂等，装配期注册一次即可（见下）。
- **开关**：`yomi.idempotency.enabled=true`
- **注意**：入口只有 `IdempotencyUtils`（`execute` / `run` / `key` / `newKey`），写逻辑放进 Supplier/Runnable；Redis 挂了会降级靠 DB 唯一键；幂等 key 自己设计（要按用户隔离就把用户写进 key）；key / namespace 长度上限 256 / 128（与库列一致，超限点名报错），请求指纹不限长度（组件统一取 SHA-256 摘要存储与比对）。
- **事务**：边界由调用方给，组件**不创建也不注入**事务模板——调用点在 `@Transactional` 里就直接沿用（与写用例入口同点）；没有事务时把 `TransactionTemplate` 作为 `execute/run` 的 `template` 入参显式传入（只接受 REQUIRED、非只读）；两者都没有直接在入口抛 `IDEMPOTENCY_TRANSACTION_REQUIRED`（记录不能各自自动提交：业务失败后该键会卡在处理中直到清理）。记录库跟着事务走：事务落哪个库记录就写哪个库——该库没注册抛 `IDEMPOTENCY_DATASOURCE_UNREGISTERED`，线程上另绑了别的库事务抛 `IDEMPOTENCY_FOREIGN_TRANSACTION`。
- **多数据源**：按多数据源模板装好附加库工厂后，在 `@Configuration` 里注册一次（注册名进 Redis 键与清理任务名，要稳定、各实例一致；只允许字母数字与 `- _`，装配期结束后冻结）：
  ```java
  @Bean
  SqlSessionFactory reportSqlSessionFactory(@Qualifier("reportDataSource") DataSource reportDataSource,
                                           IdempotencyDataSources registry) throws Exception {
      MybatisSqlSessionFactoryBean factory = new MybatisSqlSessionFactoryBean();
      factory.setDataSource(reportDataSource);
      factory.setDatabaseIdProvider(new DsDatabaseIdProvider());
      SqlSessionFactory sqlSessionFactory = factory.getObject();
      registry.register("report", sqlSessionFactory);   // 注册即获得自动建表 + 自动清理
      return sqlSessionFactory;
  }
  ```
- **记录清理**（`stale-cleaner-enabled=true` 时**每个注册库一个**集群定时任务，任务名 `idempotencyRecordCleaner`（主库）/ `idempotencyRecordCleaner-注册名`）：僵死「处理中」与「已过期」两类各自"限额删除 + 循环删空"——单条 DELETE 行数 `chunk-size`（默认 1000）、单轮每类上限 `max-delete-per-run`（默认 5 万）→ **清理能力 ≈ 上限 × 144（`scan-interval=10m`）= 约 720 万行/天/类**（启动日志会打印本配置的能力；写入 ≈ 不同幂等键数/天，需 ≤ 该值）；落后度量 `lag = 最旧一行已过期多久`（0=追上，持续变大即单轮容量不足）。
- **验证**：`POST /test/ds/test-idempotency/flow`

### event（`yomi-boot-java-component-event`）

- **干啥**：发件箱写库再发 Kafka；消费侧 `EventUtils` + 收件箱防重复。
- **环境**：主数据源 + Redis + Kafka；中继与保留期清理由集群定时任务（`ClusterTask`）自动驱动。
- **开关**：`yomi.event.publisher-enabled` / `consumer-enabled`
- **注意**：`eventId` 同 topic 内要唯一；消费要 RETRY 时自己 nack，别指望只不提交 offset；`onMessageNormal` 不写收件箱、业务异常只记日志仍返回 SUCCESS（失败不重投），仅用于可丢弃/可补偿场景，带 eventId 的消息用 `onMessage`；保留期清理默认关，开了收件箱保留别短于 Kafka 保留时间。
- **验证**：不依赖 Kafka：`POST /test/ds/test-event/utils-flow`；端到端需 broker + `@KafkaListener`

### oss（`yomi-boot-java-component-oss`）

- **干啥**：统一对象存储门面（S3 / RustFS / 阿里云 OSS）。
- **开关**：`yomi.oss.enabled=true`，`provider` 与各厂商 endpoint/密钥（生产用环境变量）。
- **验证**：`GET /test/ds/test-oss/flow`（需真实桶；本地可用 RustFS）

### captcha（`yomi-boot-java-component-captcha`）

- **干啥**：图形验证码（文字 / 算术），`ICaptchaService` / `CaptchaUtils`。
- **环境**：可不依赖 Redis；`store=redis` 时要 Redis ≥ 6.2。Linux 精简镜像需装字体。
- **开关**：`yomi.captcha.enabled=true`；存储 `auto` / `local` / `redis`（多实例请用 redis）。
- **注意**：**不提供 HTTP 接口**，生成/校验接口自己写；校验跟登录等同请求内完成；`verify` 一次即失效。
- **验证**：`GET /test/ds/test-captcha/generate`、`POST /test/ds/test-captcha/verify`

### desensitize（`yomi-boot-java-component-desensitize`）

- **干啥**：`IDesensitizeService.mask(策略名, 值)`；内置手机号、身份证等 12 种策略，可自定义 Bean 扩展。
- **环境**：无。
- **开关**：引依赖即生效，无配置项。
- **验证**：无演示接口，启动后注入 `IDesensitizeService` 即可；单测在组件模块内。

### httplog（`yomi-boot-java-component-httplog`）

- **干啥**：HTTP 请求/响应异步入库，脱敏走 desensitize；查询用 `IHttpLogService`。
- **环境**：开功能要主数据源；`mode=redis` 要 Redis，`mode=kafka` 要 Kafka，`memory` 零依赖但进程挂了就丢缓冲。
- **开关**：`yomi.httplog.enabled=true`；`mode=memory|redis|kafka`；脱敏词表 `yomi.httplog.desensitize.key-types`（空词表会 WARN 原样入库）。
- **redis 队列上限**：list 结构按 `yomi.httplog.redis.max-length` 有界（默认 5 万，`0=不限`），超限丢队首最旧；估算占用 ≈ max-length ×（请求体上限 + 响应体上限 + 约 2KB），超 256MB 启动期 WARN；stream 结构上限单独立项，本键不生效（启动期 WARN）。
- **保留期清理**：默认 7 天（`yomi.httplog.retention.*`），踩点由集群定时任务（Redis 锁互斥）驱动。单条 DELETE 行数 `chunk-size`（默认 1000）、单轮上限 `max-delete-per-run`（默认 20 万）→ **清理能力 ≈ 上限 × 24/scan-interval = 约 480 万行/天**（启动日志会打印本配置的能力，写入行/天 = QPS × 86400，需 ≤ 该值）；落后度量 `lag = now − 最旧一行`（指标 `yomi.httplog.retention.lag`，`lag` 持续大于 `days` 即清理追不上：调大上限或调小间隔）。
- **保留期清理只清本服务**：多服务共库时各服务清自己的行；**服务下线后其历史行不再被清理**，需人工处理。
- **超大体量**：行删是渐进式的；单服务写入 > 500 万行/天、或要求"到点即时消失"时，应改按 `create_time` 分区 + `DROP PARTITION`（需 `PK(id, create_time)` 复合主键与运行期 DDL；单独立项，非默认能力）。
- **注意**：允许有界丢失；不提供组件自带的查询 Controller，演示在 quick-starter。
- **验证**：`POST /test/ds/test-httplog/flow`；`GET .../query`、`.../detail`；保留期清理真机验证见模块内 `HttpLogRetentionCleanerIntegrationTest`（MySQL/PG 各一遍）

## quick-starter 怎么跑

## 附录：多数据源（业务自建附加库）

**主库由 ds 组件独占装配**：业务只能在 yml 里配（`spring.datasource.url/username/password`；换池用 `spring.datasource.type`，池参数按推导前缀 `spring.datasource.<池名>.*` 绑定）；
声明 `masterDataSource` / `masterSqlSessionFactory` / `masterSqlSessionTemplate` / `masterTransactionManager` 会直接启动失败——主数据源不允许被业务替换。

**第二个库及以后**你自己配数据源、`SqlSessionFactory`、`SqlSessionTemplate`、`PlatformTransactionManager`，并单独 `@MapperScan`。

要点：

1. 主库 Mapper：只写包路径即可（不写 ref 的 Mapper 约定落主库）。
2. 附加库 Mapper：`sqlSessionFactoryRef` 和 `sqlSessionTemplateRef` **两个都要写**，缺一启动会拦。
3. 附加库那套 Bean 用业务自己的名字，**不要标 `@Primary`**：`@Primary` 是"按类型解析"的唯一解，标了会抢走不写 ref 的 Mapper、`@Transactional` 与组件的库设施，组件会静默查错库——启动期绑定审计会拦下。
4. 注入附加库 Bean 时参数要带 `@Qualifier`，否则会被主库 `@Primary` 抢走。
5. 建附加库工厂时复用容器里的 `MybatisPlusInterceptor`、`List<TypeHandler<?>>`、`DatabaseIdProvider`，并挂上 `DsCrossDbGuard.of("库名", dataSource)`。
6. 一个 `@Transactional` 只打一个库；跨库用 event 等显式方案，别在一个事务里写两个库。
7. 需要库操作的组件（rbac / event / idempotency / httplog）只走主库：要让组件落别的库，请覆盖对应端口 Bean（如 `IHttpLogRepository`），不要动主库装配。

附加库配置示例见 quick-starter / ds 模块测试 `DsMultiDataSourceTest`（与历史文档模板一致）。

## 不包什么

业务域表与流程（用户、订单等）、操作审计、多租户、定时任务平台——由业务自己设计和选型。根 POM 里的 Spring Cloud BOM 仅供业务按需使用。
